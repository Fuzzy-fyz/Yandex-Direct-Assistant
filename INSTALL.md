# yandex-direct-assistant — установка и первый запуск

## Что внутри

- `yandex-direct-assistant.skill` — готовый пакет навыка для приложения Claude (Cowork и claude.ai).
- `yandex-direct-assistant/` — исходная папка навыка: для Claude Code и для правок.
- `yandex-direct-assistant/references/business-profile.md` — шаблон профиля бизнеса.

## Установка

**Приложение Claude (Cowork, claude.ai).** Загрузите `yandex-direct-assistant.skill` в разделе навыков (Skills) в настройках Claude или нажмите «Save skill» на карточке этого файла в чате. Навык должен быть включён.

**Claude Code** (если будете им пользоваться):

```bash
mkdir -p ~/.claude/skills
cp -R yandex-direct-assistant ~/.claude/skills/
```

После перезапуска Claude Code навык подхватится автоматически. Чтобы навык работал только в одном проекте, положите папку в `.claude/skills/` этого проекта.

## Профиль бизнеса

**Способ 1 (рекомендуется).** Скопируйте шаблон `yandex-direct-assistant/references/business-profile.md` в папку, где будете хранить выгрузки, заполните его и подключайте эту папку к задаче. Навык сначала ищет заполненный профиль в рабочей папке, поэтому после изменения целевого CPA или бюджета переустанавливать навык не нужно.

**Способ 2.** Заполните `yandex-direct-assistant/references/business-profile.md` и попросите Claude пересобрать и переустановить навык.

Без этих полей выводы будут ограниченными:

- главное целевое действие и цели Метрики (название и ID);
- что считается качественным и нецелевым лидом;
- средний чек и маржинальность;
- целевой и предельный CPA или ДРР;
- месячный и дневной бюджет;
- кампании, которые нельзя останавливать без отдельного согласования.

Неизвестное оставляйте как `[нужно уточнить]` — навык не будет выдумывать значения и скажет, чего не хватает. Токены, пароли и персональные данные клиентов в профиль не записывайте. Заполненный профиль, выгрузки и журнал изменений храните вне этого репозитория.

## Какие выгрузки готовить (CSV или XLSX)

- **Директ, Мастер отчётов:** срезы «Кампания» и «Дата». Метрики: показы, клики, расход, конверсии — выберите нужные цели и модель атрибуции; доход, если он настроен.
- **Директ, поисковые запросы:** полный отчёт за период, а не только топ.
- **Директ, площадки:** срез «Площадка» по кампаниям в РСЯ.
- **Метрика:** отчёт по целям с разбивкой по кампаниям Директа. Период должен быть в заголовке или по дням.
- **CRM (если есть):** ID сделки, дата, utm_campaign (лучше ещё utm_term или ClientID), статус, сумма. Имена и телефоны не нужны — скрипт всё равно их удалит.

Названия разделов в интерфейсах Яндекса могут немного отличаться. Подойдёт любая выгрузка с понятными заголовками столбцов.

## Первый запуск

Положите файлы в одну папку, подключите её к задаче в Claude и напишите, например:

> Первый запуск. В папке выгрузки за сентябрь 2026: кампании Директа, поисковые запросы, площадки РСЯ, цели Метрики и сделки из CRM. Профиль бизнеса лежит там же. Сделай базовый аудит.

Навык нормализует файлы локальным скриптом и проверит качество данных. На первом запуске он выдаёт базовый аудит: доступные данные, пробелы, структура, экономика, три возможности, три риска и план измерений на 14 дней.

Дальше можно просить, например:

- «Ежедневный отчёт за вчера, сравни с тем же днём прошлой недели».
- «Недельный отчёт за 22–28.09 с результатами подтверждённых изменений».
- «Что делать с запросом “…”: 5 кликов, 700 ₽, 0 конверсий?»

## Безопасность

- По умолчанию навык только анализирует данные. Изменения возможны только после подтверждения конкретных номеров («Подтверждаю 1 и 3»), и на этом этапе вы вносите их сами по пошаговой инструкции.
- Фразы вроде «давай» или «оптимизируй» навык не считает подтверждением.
- Скрипт `normalize_exports.py` работает локально: сетевые соединения заблокированы, исходные файлы не меняются, столбцы с персональными данными удаляются.
- Не отправляйте токены в чат. Если это случилось, отзовите токен.

## Подключение API позже

Схема описана в `yandex-direct-assistant/references/api-roadmap.md`. Коротко, понадобятся:

1. Доступ к API Директа для вашего аккаунта и OAuth-приложение Яндекса. Для Метрики достаточно прав только на чтение статистики.
2. Локальный `.env` для токенов, исключённый из Git (`.gitignore` уже есть), и `.env.example` без реальных значений.
3. Три отдельные команды: получение статистики (только чтение) → подготовка плана изменений → применение только подтверждённых пунктов. Применение — с пробным прогоном, проверкой лимитов, журналом и без операций удаления.
4. Проверка всей цепочки в песочнице API Директа до работы с боевым аккаунтом.
