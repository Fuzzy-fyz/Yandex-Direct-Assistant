# Будущая API-интеграция (не реализована)

Статус: **этап 1 — только выгрузки CSV/XLSX**. Ничего из описанного ниже не реализовано. Файл нужен, чтобы объяснить пользователю безопасную схему подключения, когда он сам решит перейти к следующему этапу. Не создавайте код API-интеграции и не запрашивайте токены, пока пользователь явно не начнёт этот этап отдельной задачей.

## Три независимых шага

API-интеграция делится на три шага, каждый — отдельная команда со своими правами.

1. **Получение статистики (только чтение).**
   Отчёты Директа и Метрики загружаются в локальную папку в том же формате, что и ручные выгрузки, и проходят через `scripts/normalize_exports.py`. Шаг не имеет методов записи. Для Метрики используется доступ только на чтение статистики; для Директа — минимально необходимые права, по возможности отдельный аккаунт-представитель с ограниченной ролью. Точные названия прав проверить в документации Яндекса на момент подключения.

2. **Подготовка плана изменений (без записи).**
   Ассистент формирует файл плана: дата, номер версии, нумерованные действия с ID объектов, текущие и предлагаемые значения, проверка по `change-limits.md`, исходные показатели, дата проверки и условие отката. На этом шаге API вызывается только для чтения текущих настроек.

3. **Применение только подтверждённого плана.**
   Отдельная команда принимает файл плана и список подтверждённых пользователем номеров. Перед применением:
   - сверяет контрольную сумму плана — изменённый после подтверждения план не применяется;
   - заново читает текущие настройки и останавливается, если они отличаются от исходных в плане;
   - повторно проверяет лимиты из `change-limits.md`;
   - по умолчанию работает в режиме пробного прогона (dry-run) и сначала проверяется в песочнице API Директа;
   - применяет действия по одному, останавливается на первой ошибке, пишет журнал;
   - не содержит операций удаления.

## Хранение доступа

- Токены — только в локальном `.env` (или в системном хранилище ключей), который указан в `.gitignore`. В репозиторий кладётся только `.env.example` без реальных значений.
- Токены никогда не вставляются в чат, Markdown-файлы, исходный код или отчёты.
- По возможности — раздельные токены для чтения и для применения изменений; токен записи хранится отдельно и используется только шагом 3.
- При подозрении на утечку — немедленно отозвать токен в настройках OAuth Яндекса.
- Рекламные и CRM-данные не передаются сторонним сервисам; запросы идут только к API Яндекса.

## Что понадобится от пользователя на этом этапе

- Доступ к API Директа для своего аккаунта (заявка на доступ в интерфейсе Директа) и зарегистрированное OAuth-приложение Яндекса.
- Номер счётчика Метрики и ID целей, которые считаются целевыми.
- Решение, какие кампании и типы действий вообще разрешено менять через API.
- Отдельная проверка всей цепочки на песочнице до работы с боевым аккаунтом.
